Features

Markdown as the source of truth

Models, methods, APIs, pipelines and providers are all written as natural-language Markdown. Optional frontmatter (e.g. method: POST) is allowed but never required.

Folder-based routing

Entry points live in api/{definition}/{version}/{feature}/{feature}.md and route to /{definition}/{version}/{feature}. Versions are path-only (v1, v2, …); v1 supports HTTP GET, POST, PUT and DELETE.

Reviewed lock files

Every source compiles to a structured .lock.md. Locks touching security items always need human confirmation, bound to the commit hash; high-risk changes need two non-author approvers.

Signed manifest & serverless runtime

Confirmed locks are merged into a signed manifest. Each request runs with a cold start (p95 target under 1 second); the runtime never reads source Markdown.

Deterministic validation

An independent validator checks lock integrity, routing, pipelines and auth, providers, RLS and public access. The compiler has no network or tool access, and its model snapshot is pinned via a compiler hash.

Built-in account security

Refresh tokens rotate on every use (reuse revokes the family), access tokens last at most 1 hour, passwords need 12+ characters plus a breached-password check, and 5 failures in 15 minutes lock an account.

Tenant isolation

PostgreSQL providers by default, row-level security, DDL and TRUNCATE are forbidden in locks, and public writes are tightly limited with quotas, field allow-lists and audit logs.

Operations

RFC 9110 status codes, structured logs, an emergency kill switch that disables an endpoint within 30 seconds (p99) without redeploying, and supply-chain protection via CODEOWNERS.
