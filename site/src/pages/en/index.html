How it works

One Markdown file in. A real API out.

The example below follows §11.5 of the spec: a v2 endpoint that reads a user.

compile · review · sign

In between, the compiler writes get-user.lock.md with fixed sections (## Route, ## Request, ## Response, ## Transform, ## Steps, ## Errors). The runtime only ever reads confirmed locks — never your prose.

Three stages

From intent to production.

  1. 01

    Source

    Write {feature}.md in natural language: what it does, input, output, errors and permissions.

  2. 02

    Lock

    The compiler emits a structured {feature}.lock.md. An independent, deterministic validator checks it, and an owner confirms it in the PR.

  3. 03

    Manifest

    On deploy, confirmed locks are merged into a single signed manifest. Each request runs serverless with a cold start.
